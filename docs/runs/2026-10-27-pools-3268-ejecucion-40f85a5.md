### 2.2 `scipy` faltaba en `~/vtflow`

`preextract.py --hard-aniso` (y con él `--hard-axis-frac`) usa
`scipy.ndimage.distance_transform_edt` en
`hard_negatives.axis_distance_to_positive`. El import es perezoso, así que
`preextract.py --help` pasaba igual y el job moría con el primer espectro:

```
ModuleNotFoundError: No module named 'scipy'
```

Se instaló `scipy 1.18.1` (`pyproject.toml` ya lo declara: `scipy >=1.9`). El
entrenamiento no lo necesita: las distancias `d1`/`d2` ya están en el `.npz`.

## 4. Generación de los pools

Se usó el wrapper, que inyecta los overrides antes de `queue` y deja copia del
`.sub` final en `htcondor/runs/`:

```bash
cd /home/nmrbox/0070/abolanos/git/mrai_p3
for pair in "a00:0.0" "a20:0.20" "a25:0.25"; do
  R=${pair%%:*}; F=${pair##*:}
  htcondor/submit.sh preextract.sub RunName=aniso_$R \
    Pool=data/pre_aniso_f2lo0_3268_f2hi4_$R PoolK=24 \
    Extra="--hard-frac 0.32 --hard-px 2 --hard-aniso 3 8 0 4 --hard-frac2 0.68 --hard-axis-frac $F"
done
```

`--pool-k` va una sola vez (`PoolK=24`). El bloque de arriba es la forma limpia;
el envío real llevaba además `--pool-k 24` dentro de `Extra`, duplicado. Es
inocuo (argparse se queda con el último, ambos 24), pero se sacó de los ejemplos
del README y del template.

| 2222671 | `pre_aniso_f2lo0_3268_f2hi4_a00` | 03:24:12 | 0 |

- Muestreo cruzado `preextract.log` ↔ `.npz` (`0000`, `0001`, `0992`, `0994`):
  coinciden `M`, `pos`, `hard` y `band2`.
- `X` es `(N, 128, 1)` float32, con `d`, `d1`, `d2`, `n_pos`, `y`.

### 5.2 Manifests

Los tres: `source` correcto, `seed 0`, `pool_k 24`, `hard_frac 0.32`,
`hard_px 2`, `hard_frac2 0.68`, `hard_aniso [3, 8, 0, 4]`. Solo cambia el cupo:
`0.0` / `0.2` / `0.25`. `scripts/pool_flags.sh` los reproduce exacto (en a00
omite `--hard-axis-frac`, que es el default 0).

### 5.3 Composición del reservorio (1000 espectros)

Por espectro: fondo **13 820** = anillo **4 422** (0.320) + banda **9 398**
(0.680) + fácil **0**. Es lo diseñado: `0.32 + 0.68 = 1.0`.

| | a00 | a20 | a25 |
|---|---|---|---|
| eje F1 en la banda (total) | 1 499 727 (0.160) | 1 879 535 (**0.200**) | 2 349 409 (**0.250**) |
| eje F1 por espectro | 1 500 | 1 880 | 2 349 |

Anillo y banda son **idénticos** entre los tres (mismos totales); lo único que
cambia es la mezcla eje:diagonal. El 0.160 de a00 es la proporción natural
(~1:5,2).

### 5.4 Capacidad por época (`bg_ratio 4`)

Cada época necesita 737 filas de anillo y 1 566 de banda. El **peor** espectro
tiene margen **+3 270** (anillo) y **+6 950** (banda). Para el cupo, el eje
necesario es como máximo 344 (a20) / 430 (a25) y el disponible mínimo es
1 668 / 2 085: nunca falta.

Simulando `choose_background` sobre los 1000 espectros: anillo 0.320 y banda
0.680 exactos, y eje/banda **media = mínimo = máximo = 0.200** (a20) y **0.250**
(a25). No hay completado con diagonal.
