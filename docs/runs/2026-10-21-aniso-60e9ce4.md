## 1. Pool anisótropo

El pool debe generarse con `--hard-aniso` para que cada `.npz` guarde `d1` y
`d2` (distancias por eje al positivo más cercano). Un pool viejo
(`data/pre_elong_2b`) no sirve: no tiene `d1`/`d2` y `train_model.py` se niega a
arrancar.

```bash
~/.pyenv/versions/tflow/bin/python scripts/preextract.py \
  --dataset /Users/abolanos/git/cheminfo/spectrum-generator/dataset \
  --ids data/train_2d_elong/manifest.json \
  --out data/pre_aniso \
  --seed 0 --pool-k 24 --hard-frac 0.55 --hard-px 2 \
  --hard-aniso 3 10 1 3 --hard-frac2 0.25 --fast
```

- `--hard-frac 0.55`: 55 % del background del pool sale del anillo
  `d <= 2 px`.
- `--hard-frac2 0.25`: 25 % sale del rectángulo anisótropo.
- El 20 % restante es background fácil.
- Salida: `data/pre_aniso/` (~7 GB para los 1000 espectros) con `manifest.json`
  que registra `hard_aniso` y `hard_frac2`.
- `--fast` se acepta por compatibilidad; no cambia el resultado.

Verificación mínima del pool:

```bash
~/.pyenv/versions/tflow/bin/python - <<'PY'
import json, numpy as np
m = json.load(open("data/pre_aniso/manifest.json"))
print(m["hard_aniso"], m["hard_frac2"], len(m["train"]), len(m["val"]))

print(z["d1"].shape, z["d2"].shape, z["d"].shape)
assert (z["d1"] <= z["d"]).all() and (z["d2"] <= z["d"]).all()
assert ((z["d1"] == z["d"]) | (z["d2"] == z["d"])).all()
PY
```

## 2. Entrenamiento

```bash
nohup ~/.pyenv/versions/tflow/bin/python scripts/train_model.py \
  --data data/pre_aniso --preextracted \
  --init Trained/Probability_2D/US/DNN_0 \
  --lr 1e-4 --batch 65536 --bg-ratio 4 \
  --hard-frac 0.55 --hard-px 2 \
  --hard-aniso 3 10 1 3 --hard-frac2 0.25 \
  --epochs 210 --patience 20 \
  --scratch /tmp/out_aniso --sync-every 5 \
  --out Trained/out_aniso \
  > /tmp/train_aniso.log 2>&1 &

tail -f /tmp/train_aniso.log
```

Puntos que **no** se pueden omitir:

- `--hard-frac 0.55 --hard-aniso ... --hard-frac2 0.25` en el entrenamiento.
  Los defaults de `train_model.py` son `--hard-frac 0.25` y banda apagada; sin
  estos flags el pool anisótropo se muestrea con otro reparto y el A/B no es
  válido.
- `--hard-aniso` y `--hard-band2` son excluyentes.
- `--hard-aniso` exige `--hard-frac2 > 0`.
- El pool y el entrenamiento deben usar la misma geometría
  (`3 10 1 3`) y el mismo `--hard-frac2`.

Salidas:

- `Trained/out_aniso/ckpt.keras`, `training.log`, `history.*` (sincronizados
  desde `/tmp/out_aniso` cada 5 épocas).
- `Trained/out_aniso_savedmodel/` al terminar (`model.export()`); es lo que
  consume `StoP3`.
- Tiempo medido en la M1: ~17 s/época, ~1–1.5 h para 210 épocas.

## 6. Si hay que repetir con otra geometría

Cambiar **a la vez** en el pool y en el entrenamiento:

```text
--hard-aniso F1LO F1HI F2LO F2HI --hard-frac2 X
```

Ablación sugerida si `F2LO=1` no alcanza: `--hard-aniso 3 10 0 3` (incluye la
cresta pura `d2=0`). Mantener `--seed 0`, `--pool-k 24`, `--hard-frac 0.55`,
`--hard-px 2` y el resto de los hiperparámetros para que la comparación sea
contra el mismo baseline.
